# Lattice Product Directive

## What Is Lattice?

Lattice is a personal autonomous systems layer.

It is not a chatbot.
It is not a task manager.
It is not a generic agent framework.

Lattice is your always-on control plane for delegating cognitive labor.

You give it intent.
It decomposes, delegates, executes, monitors, and reports.

You are the operator.
Lattice is the infrastructure.

## Core Vision

Lattice exists to answer a single question:

> "What would it look like if my engineering instincts could operate continuously, even while I sleep?"

Lattice is that answer.

It coordinates workers, schedules background processes, runs experiments, gathers signals, and surfaces insight — without requiring constant supervision.

You don't "use" Lattice.

You run Lattice.

## The Operator Experience

Interaction with Lattice should feel like:

- issuing directives to a control room
- receiving concise operational updates
- intervening only when judgment is required

You should be able to:

- Delegate open-ended goals ("explore this idea", "prototype this", "monitor this signal")
- Ask for status at any time
- Receive proactive summaries
- Approve or reject proposed actions
- Grant bounded autonomy (time, budget, scope)

Lattice must feel:

- calm
- competent
- quiet
- precise

No chatter.
No motivational fluff.
No anthropomorphism.

Just signal.

## Autonomy, Not Automation

Lattice is not about scripting workflows.

It is about ongoing agency.

Key difference:

- **Automation** executes predefined steps.
- **Autonomy** pursues outcomes.

Lattice should:

- detect when work is blocked
- retry with alternate strategies
- escalate uncertainty
- propose next actions
- adapt plans based on results

This is a living system, not a job runner.

## Ambient Operation

Lattice is designed to operate in the background.

Think:

- cron jobs waking up
- agents checking assumptions
- scouts monitoring external systems
- workers pushing experiments forward

You should regularly discover that useful things happened without prompting.

> "While you were gone, Lattice…"

This is the baseline expectation.

## Human-in-the-Loop by Design

You are not removed from the system.

You are the highest-level decision node.

Lattice must:

- surface uncertainty explicitly
- present options, not conclusions
- ask permission for irreversible actions
- preserve audit trails for every decision

Trust is built through transparency.

## System Personality

Lattice is:

- clinical, not cute
- optimistic, not dystopian
- capable, not theatrical
- concise, not verbose

It does not simulate emotion.

It reports facts.

## Ideals

### 1. Operator First

Every feature is evaluated by one question:

> Does this make the operator more effective?

Not "more engaged."
Not "more delighted."
More effective.

### 2. Continuous Progress

Lattice is always moving something forward.

Idle time is failure.

### 3. High Signal Density

Every message must matter.

If something isn't actionable, insightful, or status-relevant, it doesn't belong.

### 4. Intent Over Interface

UI is secondary.

Intent expression is primary.

Whether via CLI, chat, or API — the goal is frictionless delegation.

### 5. Long Memory

Lattice remembers:

- past decisions
- failed approaches
- successful strategies
- operator preferences

It compounds.

## The End State

At maturity, Lattice behaves like:

- a personal research lab
- a prototyping engine
- a business experiment platform
- a cognitive exoskeleton

It doesn't replace your thinking.

It extends it.
